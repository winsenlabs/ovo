# Deployment implementation evidence

Date: 2026-09-20  
Scope: durable orchestration, dispatcher/worker executables, Twilio adapter, Fargate/Compose configuration, and operations runbooks.  
Status: **production runtime paths are implemented and locally integrated; live AWS/Twilio deployment and certification remain external gates.**

## Implemented

- Plugin-only application composition through runtime `definePlugin(manifest, apply)` for PostgreSQL orchestration, SQS, ECS task protection, ECS desired-count writer, Twilio, dispatcher, worker readiness/runner, and compact-process protection/static capacity.
- PostgreSQL migration with namespaced durable jobs, attempts, transactional outbox, conditional ownership epochs, capacity-leader epochs, and mutually exclusive worker-slot states. Code is split into migration, job, outbox, worker-capacity and lease repositories.
- Real `pg` repository implementation and real AWS SDK v3 adapters for SQS send/receive/delete/visibility, ECS service desired count/readback and task protection, plus CloudWatch capacity metrics.
- Outbox publication is at least once. Duplicate queue delivery is expected; external dial ownership is conditional and epoch fenced.
- Expired `dialing` ownership is reclaimed only as `reconcile_required`, preserving the original dial request ID. The new owner can query the carrier and persist accepted/rejected/pending status but cannot enter the dial path. Currently leased and `not_before` deliveries change SQS visibility instead of deleting the receipt; pending reconciliation also retains the message.
- Worker admission order is claim → full readiness → task protection → durable dial intent → provider call. Readiness/protection failures do not dial. Job lease, SQS visibility and task protection have separate renewals.
- Session-route migration v2 persists worker endpoint, owner epoch, generation, dial request, carrier SID, one-time hashed handshake and terminal release gate in the same transaction as dial intent. Carrier callbacks are provider-event idempotent and monotonic; terminal states never regress.
- The gateway consumes the orchestration route authority directly. It authenticates the one-time route token, checks session/call/worker/epoch/generation, acknowledges worker authentication before readiness, validates exact-URL Twilio signatures for media and status callbacks, and projects callback state into PostgreSQL.
- The worker resolves immutable releases from the shared PostgreSQL control store. It composes the four plugin-session modes with release-snapshotted provider bindings/MCP approvals, scoped encrypted credentials, real Deepgram/OpenAI drivers, live media output, scheduler and `VoiceSessionEngine`. Simulated release drivers are never composed into the live worker graph.
- Campaign outbox delivery is wired into the dispatcher through orchestration enqueue idempotency. The worker recognizes only the candidate payload, calls the PostgreSQL campaign authorization capability exactly once after readiness/protection and immediately before dial intent, persists the authorized release/to/from/attempt payload under the current job epoch, and never dials a blocked or stale capability.
- Worker acceptance/rejection/unknown outcomes and signed gateway status callbacks project idempotent events onto the authorized campaign attempt. A pre-dial failure after authorization closes the attempt without invoking the carrier.
- Production admission now requires the immutable release cost policy, reserves the PostgreSQL budget before dial intent, meters STT/TTS/inference plus carrier elapsed time through the shared cost controller, and disposes providers before settling known usage. Budget denial never reaches the carrier.
- API and worker share `OVO_PLUGIN_MODULES`: both load only trusted installed package identifiers through `loadInstalledSessionExtensions`; the worker passes native handlers into the immutable session graph, includes only exact release-pinned plugin versions, and rejects an installed-version mismatch.
- Immutable `release.config.recording` is enforced before session composition. When false (the schema default), the worker uses the original media duplex and never starts capture or creates a recording row. When true, a production recording service is mandatory and decorates live media before the engine starts. Inbound/outbound 8 kHz mu-law audio, marks and bounded metadata persist through PostgreSQL and S3 (or an explicitly durable shared Compose volume); export input is bounded, abortable, and includes only engine-accepted customer turns plus generated agent speech with confirmed carrier playback evidence.
- The process-wide bounded speech cache is attached to the live output graph. Only exact operator-approved static phrases/announcements use cached normalized audio; dynamic responses retain streaming TTS. Cache hit/miss evidence is appended to the durable call timeline, while actual cache-miss generation continues through the provider usage/cost sink.
- A dial timeout/network/5xx after request write becomes `reconcile_required`; the worker does not invoke dial a second time, and a still-pending carrier query defers the queue receipt. Signed status callback correlation can supply the carrier SID through `DialReceiptLookup`.
- Pure capacity policy uses mutually exclusive ready-idle/reserved/active/starting/draining counts, durable eligible-job count, admission horizon, carrier/provider/AWS/spend limits, bounded steps, warm inbound floor and an explicit busy/wait/callback/human overflow choice. Stale/inconsistent/invalid inputs fail closed. Existing commitments are not scaled below when a quota drops.
- ECS desired-count writes require a PostgreSQL guard matching dispatcher authority and epoch before `UpdateService`. The guard durably records an `inflight` attempt; stale leaders are rejected before the AWS update adapter. Lease takeover cannot write while an old attempt is `inflight` or `unknown`. AWS errors become `unknown`. Desired-count readback is diagnostic only and never settles either unresolved status; release requires an explicit operator reconciliation certificate and manual SQL gate.
- Runnable dispatcher, worker and media-gateway entrypoints build to CommonJS bundles and serve health endpoints. The worker defaults to `OVO_LIVE_DIAL_ENABLED=false`; enabling dialing additionally requires protection, PostgreSQL, SQS, Twilio, shared control storage, an encrypted-store master key, an authenticated gateway connection, a certified transport assertion and passing readiness.
- The media gateway composes signed `POST /twilio/inbound` handling before the ordinary status/health handler. Admission snapshots the called-number release and variables, reserves a genuinely task-protected worker slot, and transactionally creates the accepted inbound job/session route without entering the outbound runner. The worker renews protected capacity, atomically suspends it before accepting outbound work, performs budget admission on inbound media open, and hangs up before provider composition when blocked. Verified terminal callbacks release the inbound slot and call binding.
- Worker telemetry is process-scoped and bounded: sessions seed durable sequence numbers, preserve raw versus engine-accepted transcript decisions, tee provider/inference usage, attach scheduler/operation evidence and real stage timing, and flush on shutdown. Heartbeats include measured process CPU/RSS/event-loop lag while unknown restart, quota and memory-limit values remain null.
- Terraform primary profile declares private Fargate services, public TLS ALB only, SQS/DLQ, service discovery, scoped task roles/security groups, protected one-slot workers, one dispatcher, and no Application Auto Scaling policy. Terraform ignores worker desired-count drift so only the PostgreSQL-fenced dispatcher role can write it.
- Compose secondary profile declares console/API/dispatcher/gateway, PostgreSQL, ElasticMQ and two resource-bounded one-slot workers on one failure domain. Live dialing is disabled in the example.

## Explicitly unverified production gates

1. **Storage operations:** the local PostgreSQL backup/restore and restore-fence drill passed, including tombstones, duplicate claims, fenced jobs/outboxes/campaigns and ambiguous provider evaluations. This does not establish a production object-store recovery procedure, production RPO/RTO, or a managed-database point-in-time recovery result.
2. **AWS environment:** no AWS credentials were used; no `plan` against account data, apply, deployment, IAM authorization, private routing/NAT/endpoints, Secrets Manager injection, ALB WebSocket behavior, Cloud Map convergence, ECS cold start, task-protection renewal, Fargate interruption or one-writer failover was observed. PostgreSQL serializes intent and blocks competing `UpdateService` calls, but AWS exposes no fencing token that can atomically bind an ECS update to the database epoch. If a process crashes with an `inflight` write or an API call has an uncertain outcome, takeover remains deliberately blocked because the old request might still complete. Matching ECS desired-count readback is only diagnostic and cannot release the fence: it may reflect a preexisting count before a late request arrives. Settlement requires a separately recorded authoritative/operator certificate and the documented manual SQL gate. This is fail-closed behavior, not proof of atomic cross-system fencing.
3. **Media/session transport:** actual local sockets and the complete durable authority path passed, but public ALB WebSocket idle/upgrade behavior, carrier edge latency and long-call backpressure have not been certified.
4. **Twilio:** no number purchase, outbound/inbound call, real webhook delivery, bidirectional Media Stream, transfer or hangup ran against Twilio. Local signed callback/media protocol tests do not certify a carrier account or public proxy reconstruction.
5. **SQS/AWS semantics:** the actual AWS SDK adapter compiled and is used by entrypoints; ElasticMQ exercised enqueue/delivery/delete/visibility locally, but live IAM/KMS/DLQ behavior remains untested.
6. **Scale and resilience:** no 1/10/100/1000-call load, scale-from-zero timing, warm inbound capacity, stale-metric alert, provider outage, worker crash, rolling deployment, DLQ recovery, backup/restore RPO/RTO or cost-reconciliation drill ran.
7. **Provider and business certification:** the production worker defaults to actual Deepgram/OpenAI adapters and immutable release bindings, while local end-to-end uses injected fake providers only. Real provider credentials, behavior acceptance fixtures, pricing/usage reconciliation and carrier certification remain required before enabling live dial.

Use `docs/runbooks/fargate-deployment.md` as the gate checklist. Do not set `enable_live_dial=true` merely because Terraform validates or local PostgreSQL tests pass.
